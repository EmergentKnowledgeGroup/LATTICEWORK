# Voice and Positioning

LATTICEWORK speaks with confidence earned by evidence.

## Primary identity

**Name:** LATTICEWORK
**Primary tagline:** A lattice that works.
**Primary thesis:** Complexity is not just size. It is how many boundaries stay navigable.
**Technical thesis:** Context is not architecture.
**Verification thesis:** No receipt, no claim.

## Approved positioning lines

- Same problem. Better boundaries.
- Complexity preserved. Confusion removed.
- Built in public. Explained at the root.
- Compaction should remove redundancy, not meaning.
- Architecture is what remains understandable after the context window closes.
- A sophisticated system should not require its entire history to remain simultaneously active.
- Preserve the heart. Rebuild the shape.
- The repository is the argument.
- Compatibility first. Claims second.
- Measure the system, not the mythology.

## Public tone

The tone should be:

- Technically direct.
- Calm enough to be credible.
- Sharp enough to be memorable.
- Transparent about uncertainty.
- Generous toward worthwhile upstream ideas.
- Unforgiving toward unsupported claims, including our own.
- Slightly feral only where the evidence already did the damage.

## Prohibited framing

Do not:

- Insult or diagnose upstream authors or contributors.
- Include social-media handles, profile images, or argument screenshots in canonical documentation.
- Claim motives that cannot be proven.
- Describe people as fraudulent, incompetent, dishonest, delusional, or malicious.
- Encourage contact, harassment, mass tagging, or pile-ons.
- Present preliminary measurements as verified findings.
- Describe LATTICEWORK as superior in every way.
- Claim that upstream work has no value.
- Use upstream branding in a way that creates confusion or implied endorsement.

## Pointed but acceptable framing

The project may clearly state:

- Which pinned version was measured.
- Which command produced a result.
- Which test failed.
- Which behavior diverged.
- Which source surfaces are duplicated.
- Which boundaries are implicit.
- Which change requires global context.
- Which LATTICEWORK design addresses that burden.
- Which claim remains unverified.
- Which upstream feature was genuinely good and preserved.

## The rule

**Attack the claim with evidence. Attack the architecture with measurements. Do not attack the person.**

The most effective public criticism is a repository that remains useful after the argument is forgotten.

# Origin

LATTICEWORK began after a public engineering disagreement about one-shot development, agent context compaction, and what serious long-horizon software work looks like.

The disagreement produced a testable proposition:

> A complex project should be judged not only by how much code or history it contains, but by whether its boundaries, invariants, and operational state remain navigable after the original working context is gone.

FreeLattice was publicly available under the MIT License and was presented as an example of complex human-agent software development. LATTICEWORK therefore chose the strongest possible response: preserve attribution, preserve worthwhile behavior, establish a pinned baseline, and reengineer the system in public.

The repository is the argument.

No apology is required. No personality contest is useful. No social-media screenshot can substitute for software evidence.

LATTICEWORK exists to demonstrate that:

- Context has value, but context is not architecture.
- Compaction is lossy, but loss can be bounded by durable external truth.
- Large systems can remain humane, expressive, and ambitious without making every change depend on global memory.
- Human-agent engineering becomes stronger when correction, verification, and handoff are designed into the project.
- The cleanest rebuttal to an engineering claim is a reproducible implementation.

The original disagreement explains the spark. It does not define the long-term purpose.

The long-term purpose is to build a lattice that works.
